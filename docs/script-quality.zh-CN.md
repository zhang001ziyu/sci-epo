# 篇幅与剧情因果检查

## 篇幅

系列设定可填写整集正文的下限、上限和计数单位。该范围随创作资料冻结，后续改动不覆盖旧稿。对于旧系列，只识别简报或作者要求中明确的整集范围（例如 `450–650 words` 或 `300–500 字`）；冲突或分场范围会提示作者明确设置，不静默猜测。

- 词：正文按空白分隔，包含字母或数字的片段算一词。缩写与连字符词不拆分，纯标点不计。
- 字：正文里的非空白 Unicode 字符数。
- 包含角色名、对白和舞台动作；不含总标题、梗概和场景标题。

程序计算实际篇幅，不采用模型自报数值。初稿、手动编辑和局部改稿都显示计数与范围；审稿结果另存计数报告。超出、未达或范围有歧义时标为需复核，五维模型评价不能覆盖这个结果。作品仍作为候选保留，不截断正文；采用时需要先修改，或由作者单独明确确认接受篇幅例外。

生成请求按整集目标留出余量，局部改稿请求按其他未修改场景的实际篇幅计算剩余预算。若其他场景已用尽预算，单场改稿无法保证整集达标；不会擅自扩改或解锁其他场景，也不会因篇幅或内容未通过而自动重试付费请求。

## 独立因果核查

一次真实审稿使用任务开始时捕获的同一模型配置，依次完成四个阶段（最后阶段分批请求）：

1. 因果专项：逐场核对物件、位置、资源、知情范围和时间，列出人物选择以及一个具体、更简单的替代行动；指出什么原文限制了该行动，或承认限制缺失。
2. 五维审读：独立评估故事、人物、对白、连续性和可表演性，不预先提供专项结论。
3. 原文事实与遗漏整理：不接收前两份审稿，直接从冻结剧本整理时间事实，并补查时间、账目、人物选择、连续性及其他遗漏。
4. 独立陈述审计：将原审稿和事实整理结果都视为可能出错的材料，对每项结论、限定词、推断和修改建议的全部字段反查原文。事实表不能作为事实来源，审计证据只能引用冻结原文。

专项另列“倒计时与代价”：直接核对触发事件是否作用于目标、能否绕开昂贵操作完成目标；不能把设备操作有成本等同于人物目标必然有该成本。

原审稿、原文事实整理和独立审计结果并列保留。因果缺口或不确定项不会被五维的“未发现问题”覆盖。专项必须覆盖每场，引用精确匹配；声称某条替代行动被排除时必须另给限制证据。任何阶段失败都保留已完成部分，整体记录标为需复核，不伪装成完成。

安静结束、普通日常和主动放弃不自动算缺陷。情感上不愿做，与物理上不能做分别判断。0.4.4 按具体建议授权：整体结构、覆盖和引用校验须完整；选中项目的父结论、解释及改法字段都须获支持。其他已驳回的意见保持折叠，不会作为改稿输入，也不阻挡独立核实通过的修复；真实存在的时间问题不再让其正确改法无从使用。

网页带入时保存审稿 ID 与目标 ID，提交接口再次按该剧本最新审稿、场景、精确建议文本和相同授权规则校验；陈旧或被否定的自动建议在调用模型前被拒绝。新候选保存来源，旧稿不变。作者真正编辑文本后转为作者指令，不删除草稿；作者指令仍受场景范围、锁定和既有设定约束。

## 核实审稿本身

经历时间、自动运行时间、连续劳动、间歇处理、休息与计划工时分别看待。总经历不能直接变为手工工时；即使知道自动运行时段，相减后的剩余时段也不一定全部用于劳动。疲劳、沾污和拒绝加班不自动等于失能或无法操作。核实还要求重新核对时间倍率、同一笔款项的分配及已完成/待处理货物，梗概同样作为可引用来源。

程序从不可变正文中枚举包含英文/中文时间单位、时钟或倍率的候选行，提供稳定编号与相邻上下文。模型必须为每条填写主体、具体活动、经历/工时等类别、时钟口径、事实或人物断言的性质。程序按编号绑定冻结的完整候选原行，模型补充的关系引文仍须逐字匹配来源；这避免因为模型只抄了半行而丢失限定语，但不证明其解释正确。少核对一句、编号重复或引用不符都不能算完成；时间事实存在冲突或歧义时也不能同时汇总为“无问题”。这是词面覆盖保障，不是确定性的语义判定，也不保证识别所有隐含时间表达。

每个原审稿项目都有固定编号。核实必须完整覆盖，提供原文依据；与原文冲突时还需反证，非支持结论必须给更正。更正针对审稿陈述，不是要求作者把剧本改成符合误读的样子。漏项、重复编号、虚构引用、缺更正或未检查整集时不能显示为完成。整体状态由服务器计算，不接受模型自报“通过”。

审计协议 5 为因果、压力、五维解释、遗漏改法及时间解释建立分段子编号。程序按原文标点划分片段，保存完整字段与精确 UTF-16 位置；条件、否定和省略仍须结合全文解释，分段不等于语义证明。非支持判断必须提供逐字连续出自当前片段的 `claimQuote`，不能以相邻正确内容替代被审片段。多段改法除各片段外还必须审计完整修改后的结果：只执行指定场景的具体示例和指令，其他场景保持不变，逐项检查是否仍冲突。片段都成立不代表整条方案成立，缺少全文核对的历史建议不能自动带入。父结论不能比任何片段更乐观；模型原父判断、片段判断及程序汇总分别保存。时间的五个含义字段同样覆盖。改法还须有 `suggestedSceneId`，并单独核实在该场能否完成；引文涉及的场景不等于实际编辑场景。历史缺少作用场景的建议仍可读，但不推断补填或自动带入。旧协议、缺段、伪争议锚点或父子记录不一致时暂停快捷建议。锚点存在并不保证解释成立，仍需对照原文核对主体、对象、属性、计划/完成状态及推断边界。

网页会折叠被反驳、依据不足或尚未核实的原结论，显示更正与反证，并暂停其“带入改稿”按钮。旧记录明确显示未核实；可点“仅核实这份审稿的解释与遗漏”，只增加一份带原记录关联的新审稿，不覆盖历史。原来已存在的解析错误不会在重核时被抹去。漏检检查新提出的改法单独折叠；父项和解释/改法字段均核实通过时可选择其涉及场景生成候选，未获支持或覆盖不全的改法不可带入。旧协议记录须重新审计才可授权。

模型首先从正文重建时间和收支，再对照旧审稿。同笔余额须逐处核对计划用途与实际用途，并列引用分配原话；算式平衡不证明用途一致，不能脑补转用或额外资金。

真实 Provider 先按 JSON 对象合约接收输出：当前 Chat 兼容接口发送 `response_format: {type: "json_object"}`，完成事件后仍本地严格解析。只兼容包住合法对象的唯一完整 JSON 围栏，原始文本不变；裸词、围栏外说明、非对象或损坏 JSON 均拒绝，不删词修补或换模型；编排层仅对非法 JSON 做下述有界重发。该参数不保证供应商完全遵守，也不保证字段或文学解释正确；各阶段继续执行业务校验。历史原始输出的离线解析仍保留仅给裸 `quote` 属性名补双引号的有限兼容，并记录 `normalizationNotes`，不能将离线整理称为新模型正确输出。各协议差异见 [Provider 配置](provider-setup.md)。

因果和五维审稿的 evidence 也可用冻结目录的 sourceRef/draftRef 短编号，分别绑定资料与当前场景正文；程序保留完整原句及canonical地址，标题行不能代替正文，错误来源、改词或混合冲突仍拒绝。前序结构/引文不合格时保存部分结果、将运行标失败并停止后续请求，不将字段错误当作文学问题。

独立审计另有冻结原文行目录：模型可用 `{"refId":"R1"}` 等本次目录短编号指定来源原行，程序精确绑定 `sourceId/quote/sourceRef`，全量合并时再次核对同一快照。编号不存在、元数据冲突或引用不同来源均拒绝；有效地址不证明语义支持。事实扫描保持明确引文协议，旧审计逐字引文仍兼容。

引文先做精确匹配；若仅连续空白排版不同，只有在声明的同一来源内唯一匹配时才恢复原文的连续片段。保存的 `quote` 是原始源文，`modelQuote` 保留模型原引文，恢复说明可追溯。没有大小写、标点、词语或 Unicode 近似替换，也不允许跳过说话人标签拼接；歧义或错来源仍拒绝。系统绑定的时间候选原行必须本身精确匹配，不能用这项恢复机制修补候选来源错误。

事实整理调用失败，或其结构、覆盖、引文校验失败时，保留已完成部分，停止独立陈述审计；审计调用失败则保留全部原审稿、事实整理及已完成批次。两种情况任务均失败、审稿需复核。有效地发现错误解释属于正常执行结果，不当作传输失败。非法 JSON 的单次请求至多原样重发一次，整次审稿至多增加两次，改稿至多增加一次；每次尝试写入任务记录并在网页显示。HTTP、超时、输出上限及有效语义否定不重试；独立审计批次的结构/覆盖/引用错误可在同一预算内原样重发，必须后一份独立完整通过，并保留前一份有效否定及异常尝试记录，前序审稿和事实扫描的业务校验失败仍停止，不自动采用剧本。

0.4.2 的审读进一步区分人物目标与技术手段、镜头可见事实与角色断言。没有写出某件工具，或作者禁止新增隐藏道具，都不能作为所有普通替代办法不存在的证明；使用珍贵物件也不等于永久失去它。审稿先检查已有资源与临时人工办法，再判断限制是否成立。科幻世界的明确规则仍受尊重，不要求每句普通对白都附科学解释。

人物与对白检查会核对配角是否实际履行自己的任务、是否为了衬托主角而被写笨，以及对白是在向对方提出要求、回避、试探，还是向观众播报说明。删掉说教后若只换成通用的凝视、灯光或温柔触碰，也应具体说明这些动作有没有改变决定与关系；不把安静动作本身列为禁用项。符合简报不自动等于戏剧成立，前提本身的问题应当明确提出。

## 验证边界

本地回归测试覆盖计数边界、冻结资料、篇幅例外确认、因果证据与场景覆盖、审稿与核实意见冲突、第二、第三或第四次调用失败后的记录保留，以及已带入建议在同版重审后失效时阻止提交。真实模型的内容检出与改稿效果需保留原稿和新稿逐次核对，不能用测试桩或“未发现问题”宣称稳定的剧本质量。

最后阶段按父项及其全部分段分组，普通批次最多16个输出对象、4个父项；较大的父项独占一批，硬上限32个对象，超限明确拒绝而不删段。全部冻结来源仍提供给每批。最多并发2批、总上限24批，一批失败后停止发起新批次，已在途结果仍保存。批次越界、缺项等错误与全量校验错误一起保留，不能被其他批补齐掩盖。完整审稿需要前三个请求加各审计批次；历史重核需要一个事实请求加各批次。代理超时上限为20460秒，覆盖前三个各至多1200秒的请求、24批按并发2执行的理论上限，以及最多两次额外请求和余量。模型发送有效完成事件后立即关闭读取，不额外等待上游连接结束；缺少有效完成信号仍判失败，输出上限错误单独说明。

语义核实仍由模型执行，不是确定性的自然语言证明器，也不是针对“十天”的关键词禁用。单元测试验证的是状态控制、引用、覆盖、历史保留和建议隔离；真实漏检率必须通过实际回放衡量，不能用测试桩或引文匹配宣称解释永远正确。

传输层将 Bun 的 socket idle timeout 与已配置的模型请求总时限对齐，并为逐次模型请求关闭连接复用。Bun 文档说明这两种时限不同，默认 socket idle deadline 为五分钟；不能只增大 AbortController 总时限而忽略它。[Bun timeout 说明](https://bun.com/reference/globals/BunFetchRequestInit)、[连接复用说明](https://bun.com/docs/runtime/networking/fetch)。这能消除本地传输配置不一致，并不保证供应商每次都返回完整结果。压力核查直接复用对应场景已校验的原文引用，避免要求模型重复抄写同一证据。

模型读取器现保持当前发布方案的输出与总时限，范围校验不再把 65536 输出 token 静默降为 8192。当前个人方案为 65536 tokens / 1200000 ms；该预算与剧本正文 450–650 词完全分开。超出应用支持范围的方案会明确拒绝，不静默裁剪预算。
