# 网页管理模型服务

登录 Sci-epo 后，打开左侧「模型服务」（地址为部署域名加 `/#providers`）。这是单作者工作空间的管理页。

1. **服务连接**：添加名称、API 根地址、协议和 API Key。支持 OpenAI 兼容 Chat Completions / Responses、Anthropic Messages、Google Gemini。
2. **模型目录**：选择服务，填写服务商的模型标识，设置输出预算、请求时限及服务支持的推理参数。保存后点击「测试连接」，会实际请求一次模型；收到完整 `OK` 才算通过。
3. **角色分配**：分别选择生成剧本、审稿、改稿所用的已测试模型，点击「保存并应用分配」。独立因果与五维审稿共用审稿模型，语言改编沿用改稿模型。

首次启动时，如果环境变量或 `SCIEPO_MODEL_CONFIG_FILE` 里配置了模型服务，会一次性导入为第一份服务、模型和角色分配。导入只进行一次；后续重启不会覆盖网页上的修改。

## 编辑与生效

服务和模型每次保存都会生成新版本。编辑服务后，编辑对应模型以引用新服务版本，再测试并应用到角色；保存名称或密钥不会偷偷改变已发布的角色分配。服务改地址或协议时必须重新输入该服务的密钥。正在使用的服务和模型须先从角色分配中替换，才能停用。

确认放弃未保存的编辑后，角色选择恢复为已保存的分配。停用一个未使用的服务后，它的模型会从角色候选中移除，并暂停连接测试；仍可编辑和停用这些模型。重新启用模型前，须先启用它的服务或选择其他启用的服务。

新任务固定一份配置快照，同一次审稿的两个请求不会因另一页面切换模型而混用配置。运行记录会显示实际模型和分配版本。旧页面覆盖新配置会返回冲突，刷新后再编辑。

连接测试只证明该版本在测试时能够完整响应，不代表剧本质量或永远可用。迁入的模型标为「沿用部署前的运行配置」；测试与创作都不自动重试、不在失败时换模型。已有合格版本的失败复测会保留失败信息和过去通过的资格。

## 凭据与备份

API Key 不回显、不存浏览器本地存储、不进入任务快照或错误正文。新配置在 Sci-epo SQLite 中使用 AES-256-GCM 加密，认证数据绑定服务 ID 与配置版本，密钥文件默认位于数据库同目录的 `provider.key`（权限 0600）。这沿用了 AINovel 的密文、不可变配置与版本固定机制，但使用独立的 Sci-epo 保护密钥。

备份必须同时保留 SQLite 一致快照与 `provider.key`。已有密文而保护文件丢失时服务拒绝启动，不自动生成新密钥掩盖问题。首次导入后，配置文件或环境变量只作为初始资料，网页修改以数据库为准。

所有管理 API 沿用现有单作者登录、精确 Origin、CSRF 和不缓存响应规则；匿名用户不可读取服务地址、模型目录或角色分配。多用户权限、配额、计费和自动获取供应商模型列表不在本次实现范围。
