# 多语言剧本与发布版本

2026-11-06，按作者最新选择实施：首版英文剧本、英文配音、中英文字幕，首发 YouTube 和哔哩哔哩。中文和其他语言的配音从一开始作为可选版本设计。剧本质量优先，视频制作仍是下一阶段。

## 四个独立的语言选择

| 对象 | 默认选择 | 当前行为 |
| --- | --- | --- |
| 原稿 | English / en | 系列设定选择语言；生成、审稿、局部改稿与手动版本沿用本版语言 |
| 语言改编 | 简体中文 / zh-CN | 绑定一份不可变原稿版本，逐场对读、编辑、另存和导出 Markdown |
| 配音 | English / en | 发布设置可切换中文、日语等语言；当前保存规格，尚未合成音频 |
| 字幕 | en + zh-CN | 独立可选字幕轨、双语画面字幕或无字幕母版；当前尚未生成时间轴文件 |

界面和审稿解释暂时为中文。这与剧本内容的语言选择分开。初始界面提供英语、简繁中文、日语、韩语、西班牙语、法语、德语、巴西葡萄牙语；接口使用规范化 BCP-47 语言代码，便于扩展。列出语言不等于该语言的创作质量已经验收。

## 改编的质量与版本约束

- 原稿先解决人物意图、因果、科技规则和代价。中文设定可以生成英文剧本，输入语言不决定输出语言。
- 语言改编应保留剧情事实、人物意图、场景顺序和结局，对笑点、口语与语气进行自然改写。不是把句子机械逐词替换。
- 人名、地名与科技名词使用冻结在原稿上下文中的术语表。术语表的修改会影响后续版本，不覆盖旧稿。
- 每份译稿保存 `sourceRevisionId`、语言、场景编号与自身版本。编号、数量、顺序不匹配的模型输出不保存为有效译稿。
- 原稿和译稿分别保留版本。修改原稿后，旧译稿仍归属于旧原稿，界面提示需要复核；新原稿的制作规格不会把旧译稿算作已具备。
- 译稿的保存和导出都是候选记录。目前由作者逐场核对事实、遗漏、角色语气、笑点和可表演性，尚未实现独立的译稿审批及自动翻译质量审稿。
- 真实模型失败必须记录为失败。中英文演示是预置样例，仅用于操作验证，不能充当真实改编或质量验收。

## YouTube 与哔哩哔哩

YouTube 的首选包为无字幕母版、英文音轨、分别上传的英文和中文字幕轨，另配各语言的标题与简介。观众选择一个字幕语言；默认播放器的单轨选择不等于同时显示两种语言。双语同时显示需要合并后的双语字幕或烧录画面。

YouTube Studio 支持添加语言并上传字幕文件；同视频的多语言音轨还需要频道具备对应功能，音轨应与同一剪辑长度匹配。不同配音引起明显时长或镜头变化时，保留独立版本，不强行套在同一时间轴。参考：[添加字幕](https://support.google.com/youtube/answer/2734796?hl=en)、[多语言音轨](https://support.google.com/youtube/answer/13338784?hl=en)。

哔哩哔哩首发也可以用英文配音，另导出有中文字幕或中英双语画面字幕的版本。画面字幕始终显示；CC 字幕能否上传、如何选择以该账号投稿后台实际能力为准。本次没有验证用户 B 站账号的字幕权限。

始终保留无字幕母版。字幕字数、分行、遮挡和停留时间需要在手机上复核；双语画面字幕不强制用于所有平台。

## 视频阶段的交付约束

制作包应绑定原稿版本、译稿版本、配音语言、配音资产、剪辑版本及字幕轨版本。正式配音确定后再对齐字幕时间码，不根据剧本文字量伪造已完成的 SRT。

目标交付：`clean.mp4`、各语言音轨、`en.srt`、`zh-CN.srt`／VTT，以及可选的双语烧录视频。中文配音与英文配音若节奏不同，各自有时间轴。日后增加语言时复用相同结构。

目前“导出制作规格”提供 JSON 清单，明确标记 `productionStatus: planning_only` 和 `timedSubtitlesAvailable: false`，列出缺失的语言版本及待制作步骤。不会把规格文件显示成已经生成的视频。
